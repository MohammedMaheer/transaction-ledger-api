# Transaction Ledger API v1

Base URL: `http://localhost:8000/api/v1`. Send `Content-Type: application/json` on POSTs.
Interactive contracts are available at `/docs`, `/redoc`, and `/openapi.json`.
Authentication is outside this assessment's scope.

UUIDs below are illustrative. Use the IDs returned by account creation in actual requests.
All timestamps are generated by PostgreSQL in UTC. Balances and amounts in responses are
decimal strings with exactly two decimal places. Input objects reject unknown fields.

## Endpoints

| Method | Path | Success | Expected failures |
| --- | --- | --- | --- |
| POST | `/api/v1/accounts` | 201 | 422 |
| POST | `/api/v1/accounts/{account_id}/transactions` | 201 | 400, 404, 409, 422 |
| GET | `/api/v1/accounts/{account_id}/balance` | 200 | 404, 422 |
| GET | `/api/v1/accounts/{account_id}/transactions` | 200 | 404, 409, 422 |
| POST | `/api/v1/transfers` | 201 | 400, 404, 409, 422 |
| GET | `/health` | 200 | 503 |

All operations may also return sanitized 500 errors for unexpected failures, 503 for
identified database unavailability, or 409 for a database timeout/concurrency conflict.

## Create an account

`POST /api/v1/accounts`

Request:

```json
{"name": "John Doe"}
```

`name` is required, must be a string, is trimmed, and must contain 1-200 characters after
trimming. Balance, ID, timestamps, and any other additional fields are forbidden.

201 response:

```json
{
  "id": "7be82144-dfd7-45f7-8158-81f4f0133b93",
  "name": "John Doe",
  "balance": "0.00",
  "created_at": "2026-10-26T14:30:00Z"
}
```

422: missing/blank/non-string/overlong name, null characters, or extra fields (including
`"balance": "0.00"`). Account names need not be unique.

## Create a credit or debit

`POST /api/v1/accounts/{account_id}/transactions`

Request:

```json
{
  "type": "credit",
  "amount": "100.00",
  "description": "Initial deposit",
  "reference_id": "DEP-001"
}
```

| Field | Rules |
| --- | --- |
| `type` | Required, exactly `credit` or `debit` |
| `amount` | Required decimal string, positive, at most 16 whole digits and 2 fractional digits |
| `description` | Optional string, defaults to `""`, maximum 2,000 characters |
| `reference_id` | Required trimmed nonblank string, maximum 100 characters; unique per account |

`"100"`, `"100.0"`, and `"100.00"` are valid amounts. Numeric JSON values, negative values,
zero, exponent notation, `NaN`, infinity, signs, surrounding whitespace, leading zeros,
and extra fractional digits are rejected. Strings cannot contain null characters.

201 response:

```json
{
  "id": "2a6864f6-179f-44d0-9b56-cdc2e7075de3",
  "account_id": "7be82144-dfd7-45f7-8158-81f4f0133b93",
  "type": "credit",
  "amount": "100.00",
  "description": "Initial deposit",
  "reference_id": "DEP-001",
  "created_at": "2026-10-26T14:31:00Z"
}
```

Credits increase the balance; debits decrease it. The entry and balance change are one
atomic operation. Failures leave both unchanged. An exact-balance debit is permitted.

- 400 `INSUFFICIENT_FUNDS`: debit exceeds current balance.
- 400 `BALANCE_LIMIT_EXCEEDED`: credit would exceed `9999999999999999.99`.
- 404 `ACCOUNT_NOT_FOUND`: account does not exist.
- 409 `DUPLICATE_REFERENCE`: this account already has that reference, regardless of payload.
- 422 `VALIDATION_ERROR`: invalid body, fields, amount, type, or path UUID.

The same reference on another account is allowed. References are case-sensitive after
trimming. Repeating the request returns 409 and never applies the amount a second time.
There are no update or delete endpoints for transactions; unsupported methods return
404/405 in the standard error envelope.

## Retrieve a balance

`GET /api/v1/accounts/{account_id}/balance`

200 response:

```json
{
  "account_id": "7be82144-dfd7-45f7-8158-81f4f0133b93",
  "balance": "100.00"
}
```

404 for a missing account; 422 for a malformed UUID.

## Retrieve transaction history

`GET /api/v1/accounts/{account_id}/transactions?type=credit&page=1&limit=10`

| Query parameter | Default | Validation |
| --- | --- | --- |
| `type` | Both types | Optional, exactly `credit` or `debit` |
| `page` | `1` | Integer from 1 to 1,000,000 |
| `limit` | `20` | Integer from 1 to 100 |

Filtering, total counting, offset/limit, and sorting execute in PostgreSQL. Results sort
by `created_at` descending, then UUID `id` descending to break ties. Unknown query fields
return 422. The count and page share a consistent view with financial API writers.

200 response:

```json
{
  "data": [
    {
      "id": "2a6864f6-179f-44d0-9b56-cdc2e7075de3",
      "account_id": "7be82144-dfd7-45f7-8158-81f4f0133b93",
      "type": "credit",
      "amount": "100.00",
      "description": "Initial deposit",
      "reference_id": "DEP-001",
      "created_at": "2026-10-26T14:31:00Z"
    }
  ],
  "pagination": {
    "current_page": 1,
    "page_size": 10,
    "total_records": 1,
    "total_pages": 1
  }
}
```

`total_records` reflects the filter; `total_pages` is its ceiling divided by `page_size`.
An empty result returns `data: []`, `total_records: 0`, and `total_pages: 0`. A page beyond
the end returns an empty array and the actual totals. Inserts between separate page
requests can shift offsets. A missing account returns 404 even if its history would be
empty; malformed UUIDs and invalid pagination return 422.

## Transfer money atomically

`POST /api/v1/transfers`

Request:

```json
{
  "source_account_id": "7be82144-dfd7-45f7-8158-81f4f0133b93",
  "destination_account_id": "c2d35da6-fb58-40b5-a6c7-1faeb52e023d",
  "amount": "30.00",
  "reference_id": "TRF-001",
  "description": "Account transfer"
}
```

Both IDs must be valid, distinct UUIDs belonging to existing accounts. Amount, reference,
and description follow the transaction rules. Source funds must cover the full amount,
and destination balance must fit in `NUMERIC(18,2)`.

201 response:

```json
{
  "source_transaction": {
    "id": "d48bfb71-a6ea-4f6a-96d2-87d8e62cf879",
    "account_id": "7be82144-dfd7-45f7-8158-81f4f0133b93",
    "type": "debit",
    "amount": "30.00",
    "description": "Account transfer",
    "reference_id": "TRF-001",
    "created_at": "2026-10-26T14:32:00Z"
  },
  "destination_transaction": {
    "id": "76e429d3-d6eb-4dfc-a64e-334fc6098b8f",
    "account_id": "c2d35da6-fb58-40b5-a6c7-1faeb52e023d",
    "type": "credit",
    "amount": "30.00",
    "description": "Account transfer",
    "reference_id": "TRF-001",
    "created_at": "2026-10-26T14:32:00Z"
  }
}
```

Both entries appear in their respective account histories. Both accounts are locked in
ascending UUID order; both entries and balance changes commit together. Any failure
rolls back the entire transfer.

The reference is stored on both entries. If it already exists on either account, including
on a standalone transaction, the transfer returns 409 without moving funds. Exact retries
and changed-payload retries both return 409 after success. References can be reused between
disjoint account pairs. Failed operations do not reserve references. For full semantics,
see [ASSUMPTIONS.md](ASSUMPTIONS.md).

- 400: insufficient source funds or destination balance overflow.
- 404: either account does not exist.
- 409: reference collision or database concurrency conflict.
- 422: invalid UUID, self-transfer, invalid amount, missing fields, or unknown body fields.

## Health/readiness

`GET /health` (outside `/api/v1`)

200 response when the database is reachable and the required tables exist:

```json
{"status": "ok", "database": "ok"}
```

Missing tables return 503 `DATABASE_NOT_READY`. Identified database failures return 503
`DATABASE_UNAVAILABLE`; an unexpected failure returns a sanitized 500. This endpoint does
not write data and does not replace running migrations.

## Consistent errors and retries

Every handled error has this shape:

```json
{
  "error": {
    "code": "INSUFFICIENT_FUNDS",
    "message": "Account has insufficient balance",
    "details": {}
  }
}
```

Validation example (422):

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Request validation failed",
    "details": {
      "errors": [
        {"location": ["body", "type"], "message": "Input should be 'credit' or 'debit'", "type": "literal_error"}
      ]
    }
  }
}
```

Validation message text can vary with dependency versions. Missing-account details include
`account_id`. Raw request values, SQL statements, credentials, and stack traces are omitted.

| Status | Code | Meaning |
| --- | --- | --- |
| 400 | `INSUFFICIENT_FUNDS` | Source/debit balance is too small |
| 400 | `BALANCE_LIMIT_EXCEEDED` | Credited balance would exceed storage limit |
| 404 | `ACCOUNT_NOT_FOUND` | Referenced account is absent |
| 404 | `NOT_FOUND` | Route is absent |
| 405 | `METHOD_NOT_ALLOWED` | Route does not support this method |
| 409 | `DUPLICATE_REFERENCE` | An affected account has already used the reference |
| 409 | `INTEGRITY_CONFLICT` | Database constraint prevented the operation |
| 409 | `CONCURRENT_OPERATION` | Lock/statement timeout, deadlock, or serialization conflict |
| 422 | `VALIDATION_ERROR` | Body/path/query validation failed |
| 500 | `INTERNAL_ERROR` | Unexpected failure; no internal details disclosed |
| 503 | `DATABASE_UNAVAILABLE` | Identified temporary database failure |
| 503 | `DATABASE_NOT_READY` | Required tables are absent |

On a network error or retryable concurrency failure, retry with the **same** reference
and payload. A prior committed request then returns 409 instead of applying twice. Inspect
account history to reconcile an uncertain result; never generate a new reference simply
because a response was lost. The API performs no automatic financial-operation retries.
